# 副業Webデザイン案件の進め方（受注〜納品）

このシステムを使った、初心者でも事故なく納品するための流れ。

## 1. 案件を探す
クラウドワークス／ランサーズ／ココナラ／SNS（X・Instagram）／知人紹介。
最初は **バナー（単価3,000〜10,000円）** → **LP（5〜20万円）** → **サイト（10〜50万円）** → **UI/UX（時給制・継続）** の順にステップアップ。

### 実績（ポートフォリオ）がない時
`node tools/new-project.mjs` で架空案件を3〜5本作り、`render.mjs` の画像をポートフォリオに載せる。
（例：架空のカフェLP、架空ジムのバナー5サイズ、架空アプリのUI）。架空であることは明記する。

## 2. ヒアリング（`briefs/TEMPLATE.md` を埋める）
目的・ターゲット・競合・参考サイト・好き/嫌いなテイスト・必須要素・素材の有無・納期・予算・修正回数・納品形式。
**「好きなサイト3つ・嫌いなサイト1つ」を聞く**と方向性のズレが激減する。

## 3. 提案（方向性を2〜3案）
```bash
node tools/search.mjs --genre lp <業種> <目的>
node tools/new-project.mjs --brief briefs/<案件>.md --genre lp --name <案件>
```
`BRIEF.md` の **代替案** から方向性の違う案を2つ選び、`--ref <ID> --name <案件>-b` でもう1案作る。
各案の FV だけを作って画像（`render.mjs`）で見せる → 選んでもらってから全体を作る（手戻り防止）。
提案文には `BRIEF.md` の「コンセプト」「配色の意図」「UX法則」をそのまま使うと説得力が出る。

## 4. 制作
- Codex に「projects/<案件>/BRIEF.md に従って制作して」と指示
- 文言・写真をクライアント素材に差し替え（素材がなければ有料/無料ストックフォト、生成AI画像は商用可のものだけ）
- `node tools/check.mjs <project> --browser` でエラー0に

## 5. 確認・修正
- PC/SPのスクショ（`render.mjs --fullpage`）と、確認用URL（Netlify Drop / GitHub Pages / Vercel に一時アップ）を送る
- 修正は「まとめて」「回数を決めて」受ける（例：2回まで無料）

## 6. 納品
`delivery/<案件>/` に：
- 制作物（HTML一式 or PNG/GIF/MP4）
- `README.txt`（ファイル構成、更新方法、フォーム設定、使用フォント・素材のライセンス）
- バナーは媒体の入稿規定（サイズ・容量・ループ回数）に合わせたファイル名で

## トラブル回避
- 契約前に「修正回数・納期・著作権の扱い・素材の用意」を文章で合意
- 写真・ロゴ・文章の権利はクライアント側の責任であることを明記
- 着手金（30〜50%）を受け取ってから制作
